# 输出契约

所有阶段由当前 Codex 在同一个主 turn 内顺序完成，通过文件衔接，不交给子代理或新的推理会话。脚本只做文件处理和结构校验。所有文件使用 UTF-8。

## article.json 与 source.md：来源材料

提取脚本生成来源元数据、完整原文与正文类型。使用浏览器或其他网页读取能力恢复正文时，只根据实际取得的内容补充，不能凭摘要补造原文。

```json
{
  "schema_version": 1,
  "kind": "article",
  "source_url": "https://example.com/article",
  "resolved_url": "https://example.com/article",
  "title": "原文标题",
  "author": "原文作者",
  "images": []
}
```

- `source_url` 保留输入的 HTTP(S) 网址，`resolved_url` 是实际读取的网址。
- `title`、`author` 取自原文；未知作者用空字符串，不推测。提取器提供的站点、语言、正文等附加字段可以保留。
- `kind` 是 `article` 或 `link_card`；后者表示仅取得元信息，没有取得正文。
- 纯文本提取时 `images` 为空；使用已有来源材料时可以保留其图片清单，但文本模式不读取、选用这些图片。
- `source.md` 在开始分段后保持原样。行号从 1 开始、包含元信息与空行，作为后续定位依据。浏览器恢复时也保存实际读到的完整正文，不截图。

## blocks.json：第一阶段分段摘要

```json
{
  "schema_version": 1,
  "blocks": [
    {
      "id": "block-01",
      "title": "具体的主题标题",
      "summary": "本主题的实质中文摘要，包含主要论点、机制与证据。",
      "source_ranges": [{"start_line": 12, "end_line": 35}],
      "preserve": ["该主题需要保留的关键数字、机制、案例或限定条件"]
    }
  ]
}
```

- 至少一个块；每个块对应最终串文的一个主要论点或独立叙事阶段，数组顺序为最终阅读顺序，ID 唯一且用于段落文件名。相关子主题、人物、案例和时间节点可以放在同一块，原文阅读批次或小节不与最终段落一一对应。
- `source_ranges` 至少一个范围，起止为 `source.md` 的有效正整数行号，包含首尾。一个主题散布在原文多处时，使用多个范围。
- `summary` 是已完成的分段摘要，不是标题或一句占位说明；`preserve` 是支撑主要论点所必需、可对照原文的关键事实清单，不罗列全部细节；短文没有额外关键事实时可为空。
- 分段完成后检查主要论点覆盖和相邻块是否可以合并。段数由最终阅读主线与用户要求决定，不固定段数。无需保存分段取舍的思考过程。

## drafts/<id>.json：第二阶段单段成稿

```json
{
  "id": "block-01",
  "title": "具体的主题标题",
  "text": "依据该段摘要、关键事实与原文改写的中文百科正文。",
  "image_ids": []
}
```

每个规划块对应一个文件，ID 必须一致。当前 Codex 按规划顺序逐段改写、保存、重新读取和核对；处理本段时不重新划分整篇文章。合并核对阶段若需调整分段，先更新规划，再重写受影响的草稿，保持规划与成稿一致。`text` 不含文档 H1、重复段标题、图片 Markdown、图片/嵌入 HTML 或 `<mw:...>` 标签；必要的内部子主题使用 H3。文本模式 `image_ids` 固定为空。

## thread-meta.json：合并元信息

```json
{
  "title": "生成的中文标题",
  "summary": "简短导语。",
  "tags": ["具体主题"],
  "images": []
}
```

所有字段必填。`title`、`summary` 非空，标签为无重复字符串数组，可为空。纯文本模式 `images` 固定为空。全文标题与导语在各段完成后生成。

## thread.json 与 thread.md：最终结果

组装脚本按 `blocks.json` 的顺序读取全部段落，将元信息与段落合为：

```json
{
  "schema_version": 1,
  "title": "生成的中文标题",
  "summary": "简短导语。",
  "tags": ["具体主题"],
  "blocks": [
    {"id": "block-01", "title": "主题标题", "text": "段落正文。", "image_ids": []}
  ],
  "images": []
}
```

最终契约保持兼容：上述字段必填且不增加其他字段；标题、导语、段落 ID、标题和正文非空；至少一个段落，ID 唯一。来源 URL、原始标题与作者由渲染器从 `article.json` 读取，不重复维护。

渲染器生成文档标题、来源和作者、导语、各段正文及标签。需要修订时修改对应段落文件或元信息，再组装渲染，避免 JSON 和 Markdown 分别演变。

`kind: link_card` 时只生成一个块，全部内容仅依据页面元信息，不宣称总结了正文；渲染器添加“页面摘要（未取得正文）”提示。

显式图文模式的图片字段与限制见 [图文模式](image-mode.md)。
