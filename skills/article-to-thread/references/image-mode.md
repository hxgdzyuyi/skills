# 显式图文模式

仅在用户明确要求配图、图文或保留原图时使用。正文仍由当前 Codex 在同一个主 turn 内按分段总结、逐段改写、合并核对的顺序完成。

## 提取与选择

提取命令省去 `--text-only`，读取 `article.json.images` 的原文图片清单。每项包含原文 HTTP(S) `url`、稳定 `id`、`alt`、`caption`、`context`；ID 由 URL 的 SHA-256 前 16 位生成，描述不参与身份判定。

- 结合图注与上下文关联主题；需要理解图表且有可用原图读取能力时查看原图，不对网页或浏览器截图。无法直接读取时不猜测视觉细节，依据已有图注，或省略无法确定的图片。
- 排除广告、头像、追踪像素、装饰和无关图片，不强制使用全部图片。图片读取失败不阻止文字交付。
- 每张采用的图片只在最相关的一段出现，用原文 ID 填写该段成稿的 `image_ids`。正文不手写图片 URL 或图片标签。
- 成稿保持原始图片链接，无需上传或生成新图。用户明确要求本地图片时，再按可用媒体读取能力处理。

## 元信息图片字段

`thread-meta.json.images` 只列实际采用的图片：

```json
[
  {"id": "img-e93f76856e512c4a", "description": "有依据的中文图片说明"}
]
```

ID 必须在 `article.json.images` 存在，每项必须且只能被一个段落引用，描述为非空单行字符串。不在此处增加 URL 字段。没有采用配图时，`images` 与各段 `image_ids` 都为空数组。

图片选择放在逐段正文完成之后，避免为配图改变分段主题。组装和渲染使用相同脚本，渲染器依据原图 ID 插入标准 Markdown 图片。
