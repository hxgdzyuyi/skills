## Bing History 接口

来源：DataForSEO，搜索引擎 Bing。直接使用 HTTPS API 与 Basic Auth，不使用 DataForSEO CLI。当前 Agent 仅理解主题和写建议，不提供搜索需求数据；Python 不调用模型 API。

依据 [History Live 官方文档](https://docs.dataforseo.com/v3/keywords_data-bing-search_volume-history-live/)，请求路径为 `/v3/keywords_data/bing/search_volume_history/live`，一个 Live 请求包含一个任务。参数为 `keywords`、`location_code`、`language_code`、`period`、`device`；keyword 最长 100 字符，接口会转为小写。月度历史最多 24 月，周度最多 15 周，日度最多 45 日；本版只用月度。默认时间范围与显式设备范围写入缓存身份，不改变地区或语言。

结果不是普通 search_volume/monthly_searches 表：在 `tasks[].result[]` 每词对象中读取 `period`、地区、语言及 `searches`，后者以设备类别分数组，每条含 year/month/day/search_volume。两层 status_code 都须成功；成本读取根 cost（USD）。不保留原始请求回显、provider status_message 或 task.data，以避免不可信文字和敏感回显进入缓存/报告。

## 支持市场与更新

[官方 locations_and_languages 列表](https://docs.dataforseo.com/v3/keywords_data-bing-search_volume_history-locations_and_languages/) 的文档示例包含 `zh-CN` 与中国 2156、中国香港 2344、中国台湾 2158。服务每次需要数据时使用此免费 API 的有效缓存或新响应再次核验组合；组合不在实际支持列表中则返回 unsupported，不提交付费查询。

| market 参数 | 实际查询地区 | 语言 | 引擎 |
|---|---|---|---|
| CN（默认） | 中国大陆 2156 | zh-CN 简体中文 | Bing |
| HK（显式选择） | 中国香港 2344 | zh-CN 简体中文 | Bing |
| TW（显式选择） | 中国台湾 2158 | zh-CN 简体中文 | Bing |

使用 HK/TW 不会标为中国大陆，也不会与 CN 合并评分。**支持市场不保证每个中文关键词或每类设备有历史量。** 长尾、口语化标题、公众号话题可能匹配不足。

[官方 Bing Status 文档](https://docs.dataforseo.com/v3/keywords_data-bing-status/) 说明更新一般发生在月初，`actual_data` 指前月是否已更新，`date_update` 与 last_year/last_month 标明来源最新日期和月度范围。服务动态读取这些字段，不把文档示例中的日期当作实时状态；报告同时记录来源更新日期、状态获取时间、关键词获取/过期时间、评分窗口。

月度量有数据延迟。不能把 Live 的“立即返回”解释为数据实时更新。四类设备某类缺失时不自动按零处理，可能降低可评分覆盖；须通过真实联调确认返回语义，未来若调整设备范围需明确更新公式版本。

History 没有本版可用的广告竞争指标，始终 null，不额外付费查询其他接口。广告竞争即使将来可用，也不能说明公众号内容竞争。

## 缓存、成本与失败语义

SQLite 每词缓存使用来源、实际 API origin/path、NFKC/空白折叠/小写词形、地区、语言、引擎、月度粒度、完整设备集合、接口默认 24 月时间范围、规范化版本和 production/test namespace 作为身份。本接口返回独立绝对次数，不按联合关键词集合归一化，因此每词缓存不依赖批次；付费 ledger 身份包含整个请求集合，排序后防止重排重复。测试注入 HTTP transport 必须指定独立测试 namespace。模拟模式完全不访问生产缓存。

记录标准化月份、来源、获取时间、过期时间。网络失败不存为零；no_data 可以带 TTL 短暂缓存，过期再查。默认关键数据 TTL 24 小时、市场/状态 TTL 1 小时。过期数据仍可查看但不评分，刷新失败具体说明原因。metadata 过期且刷新失败时无法确认共同窗口，也停止评分。

进程内异步锁与跨进程文件锁包围缓存检查和付费请求；SQLite 事务先记请求，再提交 API，最后记录返回成本/结果状态。相同批次默认 300 秒冷却，防止未知扣费状态被立刻重发。正常分析最多一次付费 POST；免费 GET 每个最多三次尝试，等待限幅；付费 POST 一次尝试，不跟随重定向。若请求发出后超时，成本标为未知，不能宣称没有扣费。价格由 [DataForSEO 官方价格页](https://dataforseo.com/pricing) 和 API 返回为准，未写死单价。

## 第一版边界

- 没有 Google Trends、Google 搜索量或海外中文兜底。未来补充须按引擎/地区独立展示，不能混合相对指数与绝对次数。
- 评分不反映公众号订阅关系、推荐流、封面、作者影响力、发布时间、实际 CTR 或内容质量。公式尚未用公众号行为数据校准。
- 插件给当前 Agent 返回标题、分词参考与已校验数据；选词变化会影响结果；固定相同数据、词集和窗口的公式结果可复现。
- v1 候选词和推荐标题采取原文词锚点/语法重组限制，减少无关热词、新实体和虚构事实；不做开放同义词扩展。数字、未知字段、评分字段、部分收益/新闻表态会被拒绝。模型文字校验不是完整的语义事实证明，作者仍需对照正文检查建议；建议校验失败保留数据与评分，Agent 可以只修正建议后重试；不会伪造已完成建议。
- 未在其他 OS 的凭证库或各商业 MCP 客户端上实机验收。使用官方系统后端白名单，无安全后端时拒绝工作。
