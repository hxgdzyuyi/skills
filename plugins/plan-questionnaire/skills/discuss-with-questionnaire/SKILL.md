# 讨论方案问卷

使用 `plan-questionnaire` MCP 的 `show_questionnaire` 显示问卷。主要用途是把超过 `request_user_input` 三题上限的待确认事项放在同一张长问卷里，让用户一次填写、统一提交，答案直接回到当前对话。

- 延续当前讨论，先读取已经确认的决定。四项以上可独立回答的待确认事项，集中放进一份问卷，不要机械拆成单题或三题一轮；不为凑数量重复提问。
- 每份支持 1–12 题。超过 12 题时按主题分卷并说明还剩哪些主题。只有用户明确要求逐题讨论，或后一题确实依赖前一题的答案时，才使用逐题流程。
- 单题和最多三题的简单澄清可以用宿主原生输入；用户明确要求问卷时仍使用本插件。
- 单选使用 `type: single`，多选使用 `multiple`，自由回答使用 `text`。选择题提供稳定的题目和选项 ID，以及含义明确、可比较的选项。推荐项可以标记 `recommended: true`，推荐不代表已选择。
- 默认保留 `allow_other: true`，用户可以自行说明不同方案。不要重新询问已经回答的问题。
- 同一份问卷重试时复用 `idempotency_key`；更改问题或选项时使用新键，避免覆盖已有回答。
- 调用后简短说明问卷已打开，并等待用户提交。不要用终端代填答案、调用提交工具代选，或把 pending 状态解释为接受推荐。
- 用户通过问卷提交的消息会包含问卷 ID。用 `get_questionnaire` 读取实际提交结果，按问题和选项对应含义继续；只有已授权的文档才能随选择更新。
- 收到整份问卷后，逐项核对并汇总决定，指出冲突或仍缺失的信息，再继续讨论。用户要求逐题时才在每次提交后询问下一题。不要同时再发一份重复的纯文本选择题。

`submit_questionnaire` 是界面专用工具，只有用户点击提交后才使用。问卷结果只保存到本机；网页界面通过宿主桥把用户的答复发送回同一对话。

若当前会话未加载新装的 MCP，说明需要刷新插件或重新打开会话，不声称问卷已显示。首次安装附带的 `examples/current-question.json` 是 Mira 的“反击与警戒”问题；其他讨论按当时上下文生成题目。
